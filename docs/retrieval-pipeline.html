Retrieval Pipeline — Agent Loop v2 Architecture

Unified agent loop: load_context → think ⇄ tool → post_process → END. One prompt, one loop. The LLM reasons, calls tools, and writes the answer. No separate planner, sufficiency checker, or finalizer. Sub-agents handle parallel retrieval and Office document generation.

Key design decisions (v2):

  • One prompt, one loop — the v1 multi-stage pipeline (plan → clarify → think → tool → sufficiency_check → finalize → answer_scoring → save_memory) is replaced by a single think ⇄ tool loop. The LLM reasons, calls tools, decides when evidence is sufficient, and writes the answer. No separate LLM calls for planning or sufficiency checking.
  • LLM-driven tool selection — the LLM decides which tools to call based on query type. Simple queries use search_dense directly. Complex multi-part queries use retrieve_parallel. The prompt provides explicit guidance with examples.
  • Sub-agents for complex flows — retrieve_parallel spawns parallel retrieval sub-agents for independent sub-queries. create_office_document delegates to an Office sub-agent with 4 focused tools. Sub-agents have their own iteration budgets, per-tool caps, and compact result contracts.
  • State-based pass-through — rerank_results, graph_expand, chart_generate, and create_office_document read inputs from graph state instead of requiring the LLM to pass large data arrays. office_inspect and office_edit auto-inject file_id from the last office_generate result via prepare_arguments.
  • Citation provenance — every hit carries a citation_ref with source_tool, citation_kind (chunk, file, section, range, grep, outline, table), and metadata. post_process normalizes [E1], [N](N), and bare [N] formats to [N] links with provenance.
  • Office creation guard — if the query asks for a file creation (create/generate/make + powerpoint/excel/word/spreadsheet) but create_office_document was never called, the think node forces the tool call. Prevents smaller models from writing "I have created..." without actually calling the tool.
  • Deterministic post-processing — post_process handles citation normalization, chart/office marker substitution, LastAnswerObject construction, and DB persistence. No LLM call needed when the think node already wrote the answer (precomputed_answer path).
  • Per-tool budgets — configurable caps per tool per turn (e.g. search_dense: 5, extract_data: 5, chart_generate: 3, office_generate: 3). Total tool-call budget across all tools per turn (default 20).
  • Compact SSE payload — tool observations stream only a one-line summary (~96 bytes) instead of the full result. Sub-agent events stream progress, not raw evidence.
  • Deduplication by content_hash — prevents duplicate chunks across search legs, rerank results, graph expansion, and parallel retrieval sub-agents from reaching the final generation call.
  • GPU acceleration — SPLADE sparse embeddings and cross-encoder reranking use CUDAExecutionProvider when FASTEMBED_USE_GPU=true and GPU runtime is configured.
