answer_scoring
Evaluates final answer quality: faithfulness (is every claim supported by cited evidence?), completeness (does the answer address the full query?), confidence_match (does stated confidence match evidence quality?). Computes final_confidence = 0.4 × retrieval_score + 0.3 × faithfulness + 0.3 × completeness. No automatic retry — UI decides based on scores.

Key design decisions:

  • Provenance-bound rewriting — the rewrite LLM may only introduce terms that appear in the expanded query, recent history, or previous answer. Unsupported rewrites are rejected.
  • Conditional dense leg — exact + sparse legs run first. If their reranker scores are high enough (fast-accept threshold), the dense embedding API call is skipped entirely.
  • Graduated relaxation ladder — two levels of loosening thresholds before query rewrite. If rewrite changes the query, the 2-level ladder re-runs with the new query.
  • Graph expansion is lazy — Neo4j expansion only runs when vector/sparse/exact legs are insufficient, not on every retrieval.
  • Deterministic execution check — runs after every tool round and before every think call. Short-circuits the agent loop as soon as the plan is satisfied, without waiting for the LLM to notice.
  • Deduplication by content_hash — prevents duplicate chunks across legs, synonym variants, and graph expansion from reaching the final generation call.
  • Follow-up suggestions — generated by the LastAnswerObject extraction LLM call in finalize_node (1-3 questions), emitted as la: SSE event via streaming.py, parsed by page.tsx into message.lastAnswerObject, rendered as clickable <Suggestion> buttons in answer.tsx only when streaming is complete. Clicking a suggestion calls handleFollowUp → handleSubmit, starting a new graph turn with the suggestion as the next user query.
  • GPU acceleration — SPLADE sparse embeddings and cross-encoder reranking use CUDAExecutionProvider when FASTEMBED_USE_GPU=true and GPU runtime is configured.
