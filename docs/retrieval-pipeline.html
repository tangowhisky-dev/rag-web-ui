Retrieval Pipeline — Atomic Tools Architecture

LangGraph agent pipeline: load_context → plan → clarify → think → tool → sufficiency_check → finalize → answer_scoring → save_memory. Composable atomic tools replace the former monolithic rag_retrieve.

execution_check
Deterministic execution-completeness check. Verifies all plan subtasks have successful tool results, retrieval returned docs, no un-retried failures. Forces finalize if iteration/wall-clock cap reached even when incomplete.
DETERMINISTIC
finalize
Generates the final answer. Groups chunks by document for contiguous context. Builds finalize prompt with retrieved evidence (citable docs only), conversation history, tool results, chart data. Streams answer tokens to UI. Substitutes chart markers. Normalizes citations: [E1] → [1](N) format with provenance. Emits r: (answer_rewrite) event with normalized answer + cited docs. Builds deterministic LastAnswerObject (citations, chart_options). LLM-extracted fields (summary, key_points, data, followups) filled by answer_scoring.
LLM (chat role) · streaming
answer_scoring
Evaluates final answer quality: faithfulness (is every claim supported by cited evidence?), completeness (does the answer address the full query?). Generates follow-up suggestions. Computes final_confidence = 0.4 × retrieval_score + 0.3 × faithfulness + 0.3 × completeness. Emits d: (done) event with confidence + followups. No automatic retry — UI decides based on scores.
LLM (evaluator)
save_memory
Persists final answer, plan, LastAnswerObject (citations, chart_options, followups), tool call observations, confidence scores, and faithfulness/completeness metrics to the DB message row. Emits d: (done) SSE event.
DETERMINISTIC · DB
extract_structured (background)
Fire-and-forget background task spawned after d: event. Uses a fresh DB session. Extracts summary, key_points, and data from the full answer text via a separate LLM call. Merges into the persisted LastAnswerObject without overwriting followups, citations, or chart_options. Failure is logged but does not affect the completed response. Invisible to the user.
BACKGROUND · async
END (graph)
Graph execution complete. The final state has been checkpointed and the answer persisted to DB by save_memory. Background extraction may still be running.

SSE Events
4: agent_step — node start/finish (load_context, plan, think, tool, sufficiency_check, finalize, answer_scoring). Drives the AgenticProgress chain-of-thought timeline.

pl: plan — structured plan with subtasks and tool_hints.

tc: tool_call — tool name, arguments, label. Shows in timeline as a tool step.

to: tool_observation — tool name, label, one-line summary, error. Full result stays in graph state (not streamed). ~96 bytes vs 22KB previously.

0: token — streamed answer tokens. Citations may appear as [E1] during streaming; preprocessCitations converts to [1](1) links.

r: answer_rewrite — normalized full answer + cited docs. Replaces streamed tokens with citation-normalized text.

la: last_answer — LastAnswerObject with citations, chart_options.

d: done — confidence scores, followups, message IDs. Signals stream completion.
SSE · streaming.py
Frontend: AgenticProgress + Answer
AgenticProgress (agentic-progress.tsx): renders the chain-of-thought timeline from 4: events. Tool calls (tc:/to:) appear as steps with one-line summaries. Phases: Analyzing query → Thinking → [tool steps] → Verifying → Finalizing answer → Calculating confidence. No expandable raw JSON — just labels and summaries.

Answer (answer.tsx): renders markdown answer with clickable citation popovers (CitationLink). preprocessCitations converts [E1] and [N] to [N](N) markdown links during streaming. After r: event, citations have full metadata (document_id, chunk_index, citation_kind, source_tool).

Follow-ups: rendered as clickable Suggestion buttons after streaming completes (d: event). Header: "Would you like me to explore further:".

Key design decisions:

  • Composable atomic tools — the former monolithic rag_retrieve is replaced by independent search_dense, search_sparse, search_exact, rerank_results, graph_expand, kb_read, and other tools. The LLM selects and combines them based on query type.
  • State-based pass-through — rerank_results, graph_expand, and chart_generate read their inputs from graph state (retrieved_docs, accumulated_data) instead of requiring the LLM to pass large data arrays as arguments. This eliminates fabrication and saves output tokens.
  • Citation provenance — every hit carries a citation_ref with source_tool, citation_kind (chunk, file, section, range, grep, outline, table), and metadata. The finalize node normalizes [E1] labels to [N](N) links and attaches cited docs.
  • Sufficiency check — LLM evaluates whether retrieved docs are sufficient after each tool round. If not, the agent loops back to think for more tools or broader searches.
  • Deterministic execution check — runs after every tool round. Short-circuits the agent loop as soon as the plan is satisfied, without waiting for the LLM to notice.
  • Two-call post-answer architecture — answer_scoring handles grading (faithfulness, completeness, followups) and is user-visible. extract_structured runs as a fire-and-forget background task after the d: event, extracting summary/key_points/data invisibly.
  • Compact SSE payload — tool observations stream only a one-line summary (~96 bytes) instead of the full result (~22KB). The full result stays in graph state for the LLM.
  • Deduplication by content_hash — prevents duplicate chunks across search legs, rerank results, and graph expansion from reaching the final generation call.
  • GPU acceleration — SPLADE sparse embeddings and cross-encoder reranking use CUDAExecutionProvider when FASTEMBED_USE_GPU=true and GPU runtime is configured.
